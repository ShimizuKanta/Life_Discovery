# 第2版: 仮決め機能の実装

対象: 要件定義書の2、3.1、3.4、3.5、3.6、4.2。先行するカード操作の差分も引き続き適用する。
理由: 2026-11-19の依頼により「仮決め」を第2版に実装する。

| 変更前 | 第2版 |
| --- | --- |
| 種類なし | 初めて・気づき・感動・達成・その他。登録・編集・カード表示・デッキのカテゴリ絞り込みに対応 |
| 写真なし | 任意で1枚添付。登録・編集時に追加／差し替え／削除可能。各振り返り画面で表示 |
| カレンダーなし | 月間表示、前後の月への移動、各日のカテゴリマーク、日付選択による全記録のカード一覧（アーカイブも含む） |
| ランダムなし | デッキの現在の条件に一致するカードからランダム移動。2枚以上なら現在と異なるカードを選ぶ |
| 音声入力案内なし | 標準キーボードのマイクを使う案内。独自録音・文字起こしは追加しない |

## 写真と互換性

- 選択ファイルは最大20MB。ブラウザで読み込める画像を端末内で長辺1600px以下、品質0.8のJPEGに変換する。透過部分は白で合成する。再エンコードで元画像のメタデータを除去する。
- JPEGのデータURLを記録の `photo` に保存する（上限3MiBの文字列）。元画像やファイル名は保存しない。表示と処理にネットワークは不要。非対応画像はエラーを表示し、以前の写真を維持する。
- IndexedDBのストア構成は変更しない。既存データを読み取るとき、未設定カテゴリを「その他」、写真を「なし」として扱うため破壊的な移行は不要。
- 書き出しは `schemaVersion: 2`。全記録に `category` と `photo`（データURLまたはnull）を含め、写真も1つのJSONにバックアップする。
- バージョン1・2のJSONを読み込み可能。バージョン2のカテゴリ・写真形式を検証し、写真を実際にデコードできることも確認した後、置換確認と原子的な復元を行う。不正ファイルで既存データを変更しない。
- 写真は保存容量とバックアップ容量を増やす。定期的なバックアップを推奨する。iPhoneのHEIC等は利用ブラウザでデコードできる場合に対応し、対応しない場合はJPEG等を選ぶ案内を表示する。

「保留」の通知・触覚フィードバック等は追加しない。日時判定、既存の状態・年次回答は維持する。
