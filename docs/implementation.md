# Life Discovery MVP 実装ガイド

2026-11-18

対象仕様: `life_discovery_requirements_pwa.md` の「決定」。仕様の変更はありません。

## 起動とビルド

Node.js 22以降を使用します。

```sh
npm ci
npm run dev
```

`http://127.0.0.1:4173` で起動します。GitHub Pagesのプロジェクト配信を模した `http://127.0.0.1:4173/LifeDiscovery/` でも利用できます。

```sh
npm run typecheck
npm run lint
npm test
npx playwright install chromium
npm run test:e2e
```

既存のChromeで検証する場合は、`PLAYWRIGHT_CHROME_PATH=/usr/bin/google-chrome npm run test:e2e` のように実行します。`npm run check` は上記の検証をまとめて実行します。テスト対象ブラウザの事前インストールが必要です。

`npm run build` はTypeScriptをコンパイルし、`public/` の静的ファイルとともに `dist/` に出力します。実行時の外部ライブラリ、CDN、バックエンド、環境変数、APIキーは不要です。開発用依存はTypeScript、ESLint、Playwrightのみです。

## GitHub Pagesへの公開

1. このプロジェクトをGitHubリポジトリに配置します。バックアップJSONやユーザーデータは含めないでください。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
3. `main` ブランチへのpush、または **Actions → Deploy GitHub Pages → Run workflow** で公開処理が走ります。別の既定ブランチを使う場合は `.github/workflows/deploy.yml` のブランチ名を変更してください。
4. ワークフローは型チェック、Lint、ユニットテスト、ブラウザテストを行い、成功時に `dist/` をGitHub Pagesへ公開します。

URLは通常 `https://<ユーザー名>.github.io/<リポジトリ名>/` です。すべてのアセット、manifest、Service Workerは相対パスなので、リポジトリ名への依存はありません。任意の静的HTTPSホストでも `dist/` をそのまま配信できます。Service WorkerはHTTPSまたはlocalhostでのみ動作します。

この実装作業ではGitのcommit・pushおよび実際の公開は行っていません。

## 画面と操作

- 初期画面: 発見の内容と発見日時を入力。未来日時も保存できます。
- メニュー: 左上のボタン、または画面左端から右へスワイプ。週判定・年評価の未処理件数を表示します。
- 週判定: 右スワイプで残す、左でアーカイブ、上で後回し。すべてボタンでも操作できます。カード上の縦スワイプは判定操作に使うため、ページスクロールはカードの外で行います。
- 年評価: 0〜100のスライダーと任意コメント。右スワイプで保存、左で後回し。スライダーや入力欄の操作はカードのスワイプと分離しています。
- デッキ: 左で次、右で前。新しい順／古い順、アーカイブ表示、開始日・終了日（両端含む）で絞り込みます。
- カード: タップまたはEnter／Spaceで裏返して判定・年評価を表示。長押しまたは「編集」ボタンから内容・日時の変更、アーカイブからの復元、確認付き削除を行えます。
- アーカイブからの復元は「残す」状態に戻します。既存の年評価は維持され、未評価で1年以上経過していれば年評価待ちになります。
- 後回しにした記録は待機状態のまま、次のカードへ移ります。最後のカードでは先頭に戻り、1件だけなら同じカードが残ります。
- 設定: 日本語／英語、全データJSONバックアップと復元、ホーム画面への追加案内、オフライン準備状況。

## データと日時

IndexedDBの `life-discovery` データベース（version 1）を使用します。

| ストア | 内容 |
| --- | --- |
| `discoveries` | ID、内容、発見日時、作成／更新日時、週判定と判定日時、年評価（スコア・コメント・回答日時） |
| `settings` | `preferences` キーに言語設定 |

日時はUTCのISO文字列として保存し、表示と入力には端末のローカル時間を使用します。7日後は168時間経過した時点です。年評価は端末の現在のタイムゾーンで翌年の同日・同時刻とし、2月29日は翌年2月28日に補正します。夏時間で存在しない時刻はJavaScript Dateのローカル時間補正に従います。

状態は `pending`（未判定）、`kept`（残す）、`archived`（アーカイブ）。年評価は別の `review` フィールドに保存し、元の内容を書き換えません。一度回答した発見は再び年評価待ちにはなりません。発見日時の編集は判定済み状態や回答を維持し、待機対象となる時期だけ再計算します。

起動時、画面表示時、アプリへの復帰時、表示中の30秒ごとの確認で対象と件数を計算します。入力中の年評価や開いている編集画面は自動更新で破棄しません。

## JSONバックアップ

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-11-18T12:00:00.000Z",
  "discoveries": [],
  "settings": { "language": "ja" }
}
```

エクスポートはアーカイブ・未判定・評価済みを含む全記録と設定を含みます。インポートはJSON構造、対応バージョン、日時、必須項目、IDの重複、状態と回答の整合性、スコア範囲を先に検証します。その後、ユーザーの確認を得て、記録と設定を単一のIndexedDBトランザクションで置換します。形式エラー、確認のキャンセル、トランザクションの失敗時に既存データを部分的に置換しません。

端末のストレージ削除・容量不足などに備えて、定期的にJSONを書き出してください。Safariのタブとホーム画面のPWAでデータが共有されない場合があります。移行にはバックアップを使用し、普段はホーム画面のPWAに記録してください。

## オフラインとアプリ更新

Service WorkerはHTML・CSS・JavaScript・アイコン・manifestを事前キャッシュします。初回はオンラインで開き、設定画面の「オフラインで利用できます」を確認してください。以後はオフラインでも主要操作が可能です。ファイルの保存先の選択などはOSに依存します。

ビルド時に内容ハッシュからキャッシュの世代を生成します。キャッシュ名には配信パスも含め、同一オリジンの別配信とは分離します。更新版は待機し、設定画面の更新ボタンで有効化します。入力中の内容を保存してから更新してください。新しいService Workerは自身のスコープの旧アプリキャッシュのみ削除し、IndexedDBには触れません。

## 検証範囲

- ユニットテスト: 7日の境界、うるう日、年評価の条件、JSONの正常復元・不正データ拒否、日付・並び順・アーカイブのフィルター。
- ブラウザテスト: 保存・再起動後の保持、判定・評価、スワイプと長押し、編集・復元・削除、JSON書き出しと復元／キャンセル／不正形式、言語の保持、HTMLとして解釈されない入力、オフラインでの主要操作、サブパス配信、狭い画面の横はみ出し、保存失敗時の入力維持とトランザクションのロールバック、時間経過による待機件数の更新。
- 実機のiPhoneで、ホーム画面への追加、Safari/PWA間のデータ移行、OSのファイル操作、画面端のスワイプがブラウザ操作と競合しないことを最終確認してください。Chromiumのモバイル画面検証はiOS Safari実機検証の代替ではありません。
