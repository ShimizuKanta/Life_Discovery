# Life Discovery — 要件定義書

- 2026/11/17 作成
- 2026/11/18 更新（GitHub Pages + PWAへの方針変更）
- 目的: **iPhoneで使うPWA（Progressive Web App）**を実装するための要件整理。アプリはGitHub Pagesで配信し、ユーザーデータは端末内に保存する。
- 記載ルール: **決定**＝MVPとして初期版から実装する、**仮決め**＝第2版で実装する、**保留**＝実装時期を決めず当面は対象外とする。
- 画面仕様には第2版で実装する機能も含む。MVPでは「決定」の機能のみを実装し、「仮決め」「保留」に依存するUIは表示しない。

## 1. アプリのコンセプト

**日々の「発見」を手早く記録し、1週間後に本当に大切だったか判定し、1年後にもう一度出会う。**

小さな初体験・気づき・感動・達成を残し、自分の人生における発見を振り返ることを可能にする。
さらに、時間が経ったときに意味がどう変わったかを楽しむ。
普通の日記やToDoとは違い、すべてを網羅して記録することを目指さない。

### 主な利用シーン

#### 発見
- 初めての体験をした（新しい料理、場所、趣味など）。
- 新しいことを理解した／気づいた。
- 感動した瞬間、よかった瞬間があった。
- 新しいことができるようになった。
- 苦手だと思っていた料理が好きになった。
- 失敗したけれど、何か知識を得た。
- 日常の小さな幸せを発見した／再認識した。
- 新しい習慣を始めた。
- 新しい人に出会った。

#### 振り返り
- 日曜日の夜に「今週なにかあったかな」と思い返す＆記録する（ユーザーが自発的に開く）。
- 1週間前の記録を「残す／アーカイブ」で判定する。
- 1年前の発見がどうなったかを振り返る。

## 2. MVPの機能範囲

| 機能 | 状態 | メモ |
|---|---|---|
| 発見の登録 | **決定** | 短文を素早く入力できる |
| 発見の種類 | **仮決め** | 「初めて」「気づき」「感動」「達成」「その他」 |
| 写真添付 | **仮決め** | 最大1枚、任意 |
| 音声による入力 | **仮決め** | 端末の標準キーボードの音声入力を利用。独自文字起こしや録音は作らない（利用できる環境ではMVPから標準入力を使ってよい） |
| 発見から1週間後の判定 | **決定** | 「残す／アーカイブ」。未回答は後から対応可能 |
| 1年後の振り返り | **決定** | 過去の記録を見ながら、現在の気持ち・変化を記録 |
| 判定待ち・評価待ちの件数表示 | **決定** | アプリ起動時／表示時に対象を判定し、サイドパネルなどに件数を表示 |
| 振り返り：カードデッキ | **決定** | 1枚ずつめくって見返せる。カテゴリ別フィルターは第2版 |
| 振り返り：カレンダー | **仮決め** | 月単位で発見のあった日を確認 |
| 保存・判定・評価の成功アニメーション | **決定** | 操作完了を軽くフィードバック |
| 端末内データ保存 | **決定** | IndexedDBを利用。ログイン・バックエンドなし |
| JSONエクスポート | **決定** | 全データを1つのファイルにバックアップ |
| JSONインポート | **決定** | バックアップから全データを復元 |
| PWA・オフライン利用 | **決定** | ホーム画面から起動でき、初回読み込み後は主要機能をオフラインで利用可能 |
| 日曜夜の新規発見リマインド | **保留** | 通知機能全般を当面実装しない（従来案：毎週日曜22:00） |
| 7日後・1年後の通知 | **保留** | 判定・評価のタイミング管理自体はMVPで実装 |
| 触覚フィードバック | **保留** | iPhoneのPWAでは期待どおりに利用できないため、必須としない |

**MVPではやらない:** SNS・他人との共有、AI要約、点数ベースの詳細分析、地図、音楽連携、クラウドバックエンド、複雑なタグ、毎日の連続記録（streak）強制、プッシュ通知、触覚フィードバック。

## 3. 画面構成

- 発見登録画面をデフォルトの画面とする。
- 左上にサイドパネルを開くボタンを配置し、他のページ（週判定・年評価・カードデッキ・設定。カレンダーは第2版）に移動可能。サイドパネルはスワイプでも開ける。
- サイドパネルなどに、**判定待ち・評価待ちの件数**を表示する。通知がなくても、アプリを開けば未処理の発見に気づけるようにする。
- デフォルト画面以外では、下部に **「＋発見」** のボタンを表示し、そのボタンを押すと発見登録画面にジャンプする。
- iPhoneのホーム画面に追加したPWAでの操作を主な利用方法として想定する。

### 3.1 発見登録画面

**目的:** 思いついたときに10秒程度で記録する。

- 入力項目:
  - 内容（短文・必須。複数行OK）
  - 種類（任意／初期値「その他」でもよい。**第2版**）
  - 写真（任意・1枚まで。**第2版**）
  - 発見日・時間（初期値は現在日時、変更可）
- 「＋ 発見を記録」ボタンを下部に大きく配置。
- 音声入力は、利用可能な場合は端末の標準キーボードのマイクを利用する。アプリ独自の音声入力機能は作らない。
- 保存したら軽い成功アニメーションを表示する。
- 新規登録直後の重要度評価は**しない**。
- 未来日付もMVPでは登録可。（ユーザーが自由に使える余地を残す意図）

### 3.2 1週間後の判定画面

**目的:** 当時の発見が今でも大切か、負担なく選ぶ。

- 対象: 発見日時から7日が経過した記録（判定待ち状態）。
- アプリを開いた際に対象を判定し、判定待ち一覧に表示する。通知は行わない。
- 一画面に1件の大きなカードを表示。
- 記録内容・写真・発見日・種類を表示（写真・種類は実装後に反映）。
- **右スワイプ＝残す／左スワイプ＝アーカイブ**（画面内ボタンでも同じ操作ができる）。
- アーカイブは**削除ではない**。後から参照・復元できる。
- 上スワイプで未判定として、次のカードに行く。
- 判定したら軽い成功アニメーションを表示する。
- 未判定の記録は「判定待ち」に残る。アプリを開かない期間があっても失われない。

### 3.3 1年後の評価画面

**目的:** 当時の発見の意味が今どうなっているかを残す。

- 対象: 発見日時から1年が経過し、かつ1週間後の判定で残された記録（評価待ち状態）。
- アプリを開いた際に対象を判定し、評価待ち一覧に表示する。通知は行わない。
- 一画面に1件の大きなカードを表示。
- 質問文: 「あれから1年。この発見は今どうなった？」
- 評価: 大切さに応じて、スライドバーを動かすことで0～100で評価。バーが右に行くほど赤くなるUI。
- 評価基準: 「今はそれほど大切ではない」（0%）、「今も大切」（50%）→「以前より大切」（100%）
- 変化や近況を一言入力（任意、標準キーボードの音声入力可）。
- 元の記録を上書きせず、**1年後の回答を追加情報として保存**する。
- **右スワイプ＝保存／左スワイプ＝スキップ**（画面内ボタンでも同じ操作ができる）。
- 保存したら軽い成功アニメーションを表示する。
- スキップされた記録は「評価待ち」に残る。アプリを開かない期間があっても失われない。

### 3.4 カレンダー一覧表示の振り返り画面（第2版）

**目的:** 発見がいつあったかを俯瞰する。

- 月間カレンダーを表示。左右の月移動ができる。
- 発見がある日にカテゴリマークを表示。複数ある場合は複数をタイル表示。
- 日付を選ぶと、その日の発見カードの一覧が出る。

### 3.5 カードデッキの振り返り画面

**目的:** 過去の発見を、偶然出会うような感覚で眺める。

- 1画面に主役のカードを1枚表示。
- 左右スワイプで次／前のカードを表示。（全体のカード枚数がなんとなくわかるような表示にする）
- 新しい順／古い順、アーカイブを含める、日時などの条件を切り替えて表示可能。カテゴリ別フィルターは第2版。
  - 画面上部にトグルなどの設定UIを配置。
  - デフォルト：新しい順、アーカイブなし、全期間。（カテゴリ機能導入後は全カテゴリ）
- 画面下部にランダムボタンを表示し、タップされるとランダムなカードにジャンプする。（**仮決め**）

### 3.6 発見カード

- アーカイブされた発見はグレーアウトされて表示。
- 発見カードには内容・日付を表示し、写真・種類は実装されていれば表示する。
- 発見カードをタップすると、カードが裏返り、判定状態・評価が表示される。
- 発見カードを長押しすると、編集（アーカイブから復元を含む）・削除ができる。

### 3.7 設定

- 言語切り替え（日本語・英語のみ。デフォルトは端末／ブラウザの言語設定に従う）。
- データの扱い（ブラウザ内保存であり、サーバーには送信しないことを明記）。
- **JSONエクスポート**：現在の全データをファイルに保存する。
- **JSONインポート**：ファイルを選んでデータを復元する。既存データの置換前に確認する。
- 必要に応じて、ホーム画面への追加方法とバックアップの推奨を案内する。
- 通知設定・触覚フィードバック設定は、機能を実装するまで表示しない。

## 4. 判定・評価のタイミングとデータ管理

### 4.1 タイミングのルール

| タイミング | 内容 | MVPでの動作 |
|---|---|---|
| 毎週日曜夜 | 「今週、新しい発見はあった？」 | 通知しない。ユーザーが自分でアプリを開いて記録する |
| 発見から7日後 | 「1週間前の発見、今も大切？」 | 判定待ち状態にして画面から処理できる |
| 発見から1年後 | 「あれから1年。この発見は今どうなった？」 | 評価待ち状態にして画面から処理できる |

1. 7日後・1年後の起算日は、**登録日ではなく設定した発見日**とする（変更可能な場合の整合性のため）。
2. 発見日時から7日が経過した時点で判定対象とする。年次評価も原則として発見日時と同じ時間帯から対象とする。
3. 1年後は「暦上の1年後の同じ日」を基本とする（うるう日の2/29は翌年の2/28扱い）。
4. **1年後の評価対象は1週間後に「残す」と判断した記録のみ**とする。アーカイブ記録は一覧から見られるが、年次評価待ちには含めない。
5. 判定待ち・評価待ちは保存済みデータと現在日時から判断する。**アプリ起動時・関連画面の表示時に再計算**し、未処理件数にも反映する。
6. 過去日付で登録した場合、7日経過済みなら即座に「判定待ち」にする。1年以上経過済みなら、週判定で「残す」を選んだ時点で年次評価の対象にする。
7. 発見日時の編集後は、判定・評価の対象時期を再計算する。削除した記録は対象から除外する。
8. **通知を使用しなくても、登録・判定・評価・振り返りはすべて機能する**ようにする。

### 4.2 ローカル保存とJSONバックアップ

- ユーザーの記録・状態・評価・設定は、基本的に**端末のブラウザ内（IndexedDB）**に保存する。ログインやクラウド同期は行わない。
- **エクスポート（MVP）**：発見の全記録（アーカイブ済み・未判定・評価済みを含む）と設定を、1つのJSONファイルに出力する。
- **インポート（MVP）**：保存済みJSONファイルから全データを復元する。MVPではマージは行わず、**既存データを全件置換**する。
- インポート前に置換されることを明示して確認を求める。ファイル形式や必須データが不正な場合はエラーを表示し、**既存データを変更しない**。
- 将来のデータ形式変更に備え、エクスポートJSONには `schemaVersion` を含める。各発見の識別情報と、判定・評価の情報も失わないようにする。
- 第2版で写真機能を実装する際には、写真も含めてバックアップ・復元できる方式を採用する（方式や容量対策はその段階で検討）。
- PWAやブラウザのデータが端末側の操作・設定・容量不足などで失われる可能性があるため、バックアップを推奨する。

### 4.3 PWAとオフライン利用

- アプリ本体を**GitHub Pages**で公開し、iPhoneのホーム画面に追加して使えるPWAとする。
- **Service Worker**でアプリの動作に必要なファイル（HTML・CSS・JavaScriptなど）をキャッシュし、初回オンライン読み込み後はオフラインでも利用できるようにする。
- オフラインでも発見の登録・編集、判定・評価、カードデッキの閲覧、JSONバックアップの主要操作が利用できることを目指す（OS側のファイル操作などは利用環境に依存する）。
- Service Workerは**アプリ本体のオフライン配信**、IndexedDBは**ユーザーデータの保存**を担当する。アプリ更新でデータが消えないようにする。
- Safariの通常タブとホーム画面のPWAで保存データが共有されない場合があるため、**ホーム画面のPWAを主な利用先**として案内する。
- GitHub Pagesにはアプリのコードのみを置き、ユーザーの発見データやJSONバックアップは公開リポジトリに含めない。

### 4.4 通知機能（保留）

- 日曜夜の新規発見リマインド、発見から7日後・1年後の通知は、当面実装しない。
- 将来通知を追加する場合も、通知そのものをデータの正本とせず、4.1の判定・評価ロジックを維持する。

## 5. UI/UX方針

- **操作は短く**：新規記録は1画面、判定は2択スワイプ、評価はスライドバー。
- **触って気持ちよく**：カードの重なり、スワイプ、保存時の軽いアニメーション。
- **成功時のフィードバックは視覚的に**：発見の保存、判定完了、評価完了で控えめな成功アニメーションを表示。触覚フィードバックは保留。
- **入力の強制を減らす**：写真・カテゴリー・1年後コメントは基本的に任意。
- **毎日使わせようとしない**：週1回の習慣と、自然な発見のタイミングを尊重。
- **アーカイブを怖くしない**：削除との違いを明示し、簡単に復元可能にする。
- **わかりやすい表示**：色だけでなくラベルやアイコンで区別。大きめのタップ領域、文字サイズ対応。
- **ダークモード**：MVPでは非対応。
- **色味**：温かみがある淡いグリーンを基調とする。
- **PWAらしい使い心地**：ホーム画面からすぐ起動でき、スマートフォンの縦画面・タッチ操作で使いやすい構成とする。
